# kabu screener — J-Quants API v2 (Free プラン) スクリーナー

割安な銘柄のうち、モメンタムの外れ値と「安いだけの壊れた会社」を落として
レポートを出す。日次/週次のルーティン実行を想定。

```
python screener.py --self-test    # API 不要。ロジックの自己検証 (20 項目)
python screener.py                # 通常実行
python screener.py --quick        # 初回の試し撃ち (財務の取得期間を短縮)
```

---

## 1. セットアップ

### API キー

v1 のメール/パスワード認証は廃止済み。v2 は API キー方式。

1. <https://jpx-jquants.com/ja/dashboard> でキーを発行
2. ユーザー環境変数 `JQUANTS_API_KEY` に設定

PowerShell の新規セッションではユーザー環境変数がプロセスに引き継がれないことがあるので、
ルーティンから叩くときは明示的に載せ替える:

```powershell
$env:JQUANTS_API_KEY = [Environment]::GetEnvironmentVariable("JQUANTS_API_KEY","User")
$env:SCREENER_OUT    = "C:\Users\igara\OneDrive\デスクトップ\kabu\out"
python screener.py
```

`python` は pandas / requests が入った 64bit 環境を使うこと:

```powershell
python -c "import sys, pandas, requests; print(sys.maxsize > 2**32, pandas.__version__)"
# True 3.x.x  と出れば OK
pip install -r requirements.txt
```

### 環境変数

| 変数 | 既定 | 用途 |
|---|---|---|
| `JQUANTS_API_KEY` | (必須) | v2 の `x-api-key` ヘッダに載せる |
| `SCREENER_OUT` | `./out` | 出力先 |
| `SCREENER_CACHE` | `./cache` | 取得結果のキャッシュ先 |

## 2. Free プランで動かすための設計

Free プランは **直近 12 週のデータが取れず、履歴は約 2 年**。
使えるのは銘柄一覧・株価日足・決算サマリ・決算発表予定日まで。
CSV 一括配信も使えない。この制約に合わせて次のようにしてある。

| 制約 | 対応 |
|---|---|
| 12 週遅延 | 実際にデータが返る最新営業日を自動探索して `asof` にする。レポート冒頭に遅延日数を明記 |
| リクエスト数 | `date` 指定で全銘柄を 1 回に取る。銘柄ループはしない |
| 同上 | 直近 75 日は日次、それ以前は週次サンプリング。12 か月分の株価を約 100 リクエストに圧縮 |
| 同上 | 日付単位で gzip キャッシュ。空レスポンス (休場日) も記録して再取得しない。2 回目以降は差分だけ |
| レート制限 | 429/5xx は `Retry-After` を見て指数バックオフ。リクエスト間隔も最小 0.12 秒 |

初回は決算サマリの取得 (約 320 営業日分) で時間がかかる。2 回目以降はキャッシュが効く。
とりあえず動かしたいだけなら `--quick`（財務を直近 5 か月に短縮）。

## 3. 旧版から変えたところ

### (1) 逐次フィルタ → 合成スコア

旧: PER < x かつ PBR < y で足切りしてから並べる。
閾値の内外で銘柄が消えるので、実行のたびに顔ぶれが跳ねる。

新: バリュー / クオリティ / モメンタム / 低リスクをそれぞれ
**業種内の順位スコア (rank-based z)** にして加重合成する。
順位ベースなので外れ値と分布の歪みに強い。

```
Score = 1.0 x ValueZ + 0.8 x QualityZ + 0.4 x MomentumZ + 0.2 x LowRiskZ
```

| ブロック | 構成要素 |
|---|---|
| ValueZ | 益回り (EPS/株価)、純資産倍率の逆数 (BPS/株価)、営業CF利回り、予想配当利回り |
| QualityZ | ROE、自己資本比率、営業利益率、アクルーアル `(NP - CFO)/総資産` の符号反転 |
| MomentumZ | 12-1 モメンタム、営業利益予想の期中修正率 |
| LowRiskZ | ヒストリカル・ボラティリティの符号反転 |

重みは `--w-value` `--w-quality` `--w-momentum` `--w-lowrisk` で変えられる。

### (2) 業種内で正規化する

PBR の水準は業種でまるごと違う。全体で並べると銀行・鉄鋼・不動産の羅列になって
毎回同じ顔ぶれが出る。33 業種内で順位を取ることで業種を跨いだ比較になる。
構成 8 銘柄未満の業種は全体で正規化する。`--no-sector-neutral` で無効化。

### (3) バリュートラップ対策にクオリティを入れた

「割安」だけを見ると、業績が落ちている最中の会社が上位に来る。
自己資本比率・ROE・営業利益率に加えて **アクルーアル** を入れてある。
利益と営業キャッシュフローの乖離が大きい会社は利益の質が低い。

### (4) モメンタム除外を百分位ベースに

旧: 固定シグマで外れ値除外 → 相場全体が動いた月に大量除外かゼロ除外に振れる。

新: 通過銘柄内の **クロスセクション百分位**。毎回おおよそ一定数だけ落ちる。

| 除外 | 既定 | 理由 |
|---|---|---|
| 下位 10% | `--mom-low-pct` | 下落トレンド継続。割安に見える理由が「まだ落ちている」ケース |
| 上位 2% | `--mom-high-pct` | 急騰済み。指値が刺さらずレポートに載せても実行できない |

除外銘柄は出力から消さず、`ExcludedByMomentum` と `MomentumNote` を立てて残す。
レポートの「3. モメンタム除外」節に、バリュー的には上位だが外した銘柄が並ぶ。

### (5) モメンタムの定義を 12-1 に

直近 1 か月は短期反転が混ざるので飛ばす。`P(t-1M) / P(t-12M) - 1`。
直近 1 か月リターンは `Ret1M` として別に持つ。

### (6) 分割・併合の補正を厳密化

リターンは調整後終値 `AdjC` ベース。
EPS/BPS/配当などの 1 株あたり指標は、**開示日と評価日の調整係数比** を掛けてから株価と比べる。

```
k(t)     = AdjC(t) / C(t)
SplitAdj = k(開示日) / k(評価日)
益回り   = EPS x SplitAdj / 株価
```

分割を挟んだ銘柄の PER が半分/倍になるのを防ぐ。
自己検証では、分割ありの銘柄と実質同一の対照銘柄で PER/PBR が一致することを確認している。

時価総額は使っていない。発行済株式数は期末時点の値で期ズレするため、
すべて 1 株あたり指標 x 調整係数で評価している。

### (7) 増配判定を 2 本立てに

| フラグ | 定義 |
|---|---|
| `DivIncrease` | 今期予想の年間配当 > 前期実績の年間配当 |
| `DivRevisedUp` | 同一決算期の予想配当が期中に引き上げられた (増配修正) |

本決算の開示 (`CurPerType == "FY"`) では実績が当期 `DivAnn`、予想が翌期 `NxFDivAnn`。
四半期開示では予想が `FDivAnn`、実績は前期の本決算行から拾う。この場合分けをしている。

`--quick` は前期本決算を取得範囲に含めないので `DivIncrease` が出ない。`DivRevisedUp` は出る。

### (8) 落とした理由を必ず残す

ハードゲートで落ちた銘柄も出力に残し、`ExcludeReason` に理由を書く。
レポートに内訳表が出るので、「候補が少ない」ときにどのゲートが効きすぎているか分かる。

| ゲート | 既定 |
|---|---|
| 価格データ不足 | サンプル 30 本未満 |
| 流動性不足 | 売買代金の中央値 3,000 万円/日未満 (`--min-turnover`) |
| 純資産マイナス | BPS <= 0 |
| 自己資本比率 | 15% 未満 |
| 赤字 | 会社予想 EPS・前期実績 EPS ともに 0 以下 |
| 財務データなし | BPS も EPS も取れない |

## 4. 出力

`SCREENER_OUT` (既定 `./out`) に 3 ファイル。

| ファイル | 内容 |
|---|---|
| `screen_<asof>.csv` | 全ユニバース。全ファクタ + フラグ + 除外理由 (Excel 用に BOM 付き UTF-8) |
| `screen_<asof>_top.csv` | 最終候補の上位 N (既定 30) |
| `report_<asof>.md` | 人間が読むレポート |

`report_<asof>.md` の構成:

1. サマリ（ユニバース数 → ゲート通過 → モメンタム除外 → 最終候補、ゲート除外の内訳）
2. 上位 N 銘柄（株価・PER・PBR・配当利回り・ROE・自己資本比率・12-1モメンタム・Score・増配マーク）
3. モメンタム除外（バリュー的に上位だが外した銘柄と、その理由）
4. 増配銘柄（前期実績 / 今期予想 / 増配率 / 配当利回り / 期中増額）
5. 最終候補の業種分布
6. 読むときの注意

主な列:

| 列 | 意味 |
|---|---|
| `Score` / `Rank` | 合成スコアと順位 |
| `ValueZ` `QualityZ` `MomentumZ` `LowRiskZ` | ブロック別スコア。どこで稼いだか分かる |
| `EPSBasis` | PER の分母が「会社予想」か「前期実績」か |
| `SplitAdj` | 1 株あたり指標にかけた分割補正係数 (通常 1.0) |
| `MomPct` | 通過銘柄内でのモメンタム百分位 |
| `ExcludedByMomentum` / `MomentumNote` | モメンタム除外フラグと理由 |
| `PassedGates` / `ExcludeReason` | ハードゲートの通過可否と落ちた理由 |
| `Eligible` | 最終候補か (ゲート通過 かつ モメンタム除外でない かつ スコア算出可) |

## 5. 結果を読むときの注意

- **データが古い。** Free プランは 12 週遅延。レポートの株価・指標はすべて `asof` 時点で現在値ではない。
  発注判断にそのまま使えるものではない。
- **PER の分母は会社予想を優先。** 取れない場合は前期実績にフォールバックする (`EPSBasis` 列)。
- **TTM ではない。** 四半期を跨いだ実績 12 か月利益の合成はしていない。期ズレのある会社は PER が実態とずれる。
- **スコアは相対順位。** 市場全体が割高でも上位 30 銘柄は必ず出る。絶対的な割安さの保証ではない。
- **バックテストはしていない。** 重みは経験的な既定値。ファクタの有効性を検証したものではない。

## 6. トラブルシュート

| 症状 | 対処 |
|---|---|
| `JQUANTS_API_KEY が設定されていません` | ダッシュボードでキーを発行し環境変数に設定。PowerShell では上記の載せ替えを行う |
| HTTP 401 / 403 | キーが誤っているか、プランで当該エンドポイントが使えない |
| **HTTP 410 Gone** | API が再び移行した可能性。[移行ガイド](https://jpx-jquants.com/ja/spec/migration-v1-v2) と [仕様](https://jpx-jquants.com/ja/spec) を確認し、`API_BASE` / エンドポイントパス / フィールド名を見直す |
| HTTP 404 | エンドポイントのパスが変わった可能性。仕様を確認 |
| 候補が 0 件 | レポートの「ゲート除外の内訳」を見る。`--min-turnover` を下げる、`--quick` を外す |
| 初回が遅い | 決算サマリの取得。キャッシュが効くので 2 回目以降は速い。`--quick` で短縮も可 |
| 実行が壊れていないか確認したい | `python screener.py --self-test` (API 不要、20 項目) |

異常終了時の終了コードは `2`。ルーティン側で拾える。

## 7. 参照している API (v2)

| エンドポイント | 用途 | Free |
|---|---|:-:|
| `GET /v2/equities/master` | 銘柄一覧・業種・市場区分 | 可 |
| `GET /v2/equities/bars/daily` | 株価日足 (調整後終値・売買代金) | 可 |
| `GET /v2/fins/summary` | 決算サマリ (損益・BS・配当・会社予想) | 可 |

認証: `x-api-key: <JQUANTS_API_KEY>` / ベース URL: `https://api.jquants.com/v2`
ページング: レスポンスの `pagination_key` を辿る。データ本体は `data` キー。

仕様: <https://jpx-jquants.com/ja/spec>
